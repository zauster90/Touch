# Touch — Claude Code plugin for TouchDesigner (Design Doc)

**Date:** 2026-04-16
**Repo:** github.com/zauster90/Touch
**Status:** Approved — ready for implementation planning

## Purpose

A Claude Code plugin that lets Claude build and manipulate TouchDesigner networks
through an MCP server. Functional superset of the `satoruhiga/claude-touchdesigner`
plugin, re-implemented from scratch with an emphasis on elegance, a small trusted
surface, and closing the security gaps identified during review of that project.

## Non-goals

- Browser/Chrome DevTools automation (scope creep; not a TouchDesigner concern).
- Project save/open tools (TD handles this; risk > value).
- Keyframe/animation APIs (large surface; defer to `td_execute`).
- A marketplace of multiple plugins. This repo is a single plugin.

## Architecture

Three processes, two of which we own:

```
Claude Code CLI  <--stdio/MCP-->  Node MCP server  <--HTTP+token-->  TouchDesigner
                                  (dist/index.js)                    (td_api.py in .tox)
                                         ^                                   |
                                         |  reads token from                 |  writes token on
                                         |  %APPDATA%/claude-td/token        |  first launch
                                         +-----------------------------------+
```

- **Bind:** `127.0.0.1:44444` only. Not configurable. No `0.0.0.0`.
- **Auth:** shared-secret token, generated by TD on first load, stored at
  `%APPDATA%/claude-td/token` (Windows) / `~/.config/claude-td/token` (POSIX)
  with `0600` perms. Every HTTP request carries `Authorization: Bearer <token>`,
  compared server-side with `hmac.compare_digest`.
- **DNS-rebinding defense:** server rejects any request whose `Host` header
  isn't `localhost` or `127.0.0.1`. No `Access-Control-Allow-Origin` headers
  are ever emitted, so browsers can't use it.
- **Rotation:** a `Rotate token` custom parameter button on the `.tox`
  invalidates the current token and writes a fresh one.
- **Logging:** every request logged to a bounded in-memory deque (maxlen 500)
  and mirrored to `%APPDATA%/claude-td/requests.log`. Visible live via a status
  DAT inside the component.

## MCP tools (9)

| Tool | Input schema | Backing endpoint | Purpose |
|---|---|---|---|
| `td_execute` | `code, from_op?` | `POST /execute` | Escape hatch — arbitrary Python in TD. |
| `td_pane` | `{}` | `GET /pane` | Current network editor path, position, zoom. |
| `td_selection` | `{}` | `GET /selection` | Currently selected operators. |
| `td_operators` | `path?` | `GET /operators` | List child operators at path. |
| `td_params` | `path, params?` | `GET \| PATCH /params` | Read (omit `params`) or set parameters. |
| `td_errors` | `{}` | `GET /errors` | Project errors/warnings surface. |
| `td_screenshot` | `path, width?, height?` | `GET /screenshot` | PNG of a TOP's current frame; returned as MCP `image` content so Claude sees it. |
| `td_graph` | `path?, depth?` | `GET /graph` | Structured JSON graph of a subnet — nodes + implied wires. |
| `td_create` | `type, parent, name?, pos?, inputs?` | `POST /create` | Create + optionally wire a new operator. |

## Components

### A — TypeScript MCP server (`src/index.ts`)
Single file, imports → config → token loader → `td()` fetch helper → 9 tool
registrations → `main()`. All schemas in one `zod` block. `td()` centralizes
the `Authorization`, `Host`, error-normalization logic so each handler is 3–5
lines.

### B — Python HTTP API (`toe/src/td_api.py`)
Stdlib only (`http.server`, `secrets`, `json`, `base64`, `hmac`, `contextlib`).

- `TokenManager` — creates/reads token file with restrictive perms.
- `TDHandler(BaseHTTPRequestHandler)` — validates `Host`, then token, then
  dispatches by `self.path` to one of 9 endpoint functions.
- Each endpoint returns `(status, body_dict)`; a single response writer
  handles serialization.
- Daemon thread started from the component's `onStart`; cleanly stopped on
  `onExit` and on token-rotate.

### C — Skill (`skills/td-guide/`)
Terse reference for: operator families, rendering setup, GLSL quirks,
instancing, feedback loops, and when to pick each MCP tool. No content lifted
verbatim from other projects.

## Data flow

1. User drops `TouchAPI.tox` into a project → `onStart` reads/creates token →
   binds `127.0.0.1:44444` → spawns serving thread.
2. Claude invokes a tool → `src/index.ts` reads cached token → `fetch` with
   `Authorization: Bearer …` and `Host: localhost` → Python handler validates
   both → routes → executes → logs → responds.
3. Unauthorized requests get `401` + empty body and are logged with caller IP.
4. Token rotation: button on the `.tox` → new token written → server restarted
   → MCP server fails next call with a clear "rotate detected, restart Claude
   Code" message.

## Error handling

**HTTP:** `200` ok · `400` bad input · `401` bad token · `403` bad Host ·
`404` path resolves to `None` · `500` unhandled (never leaks traceback; body
is `{error: {type, message}}`).

**MCP:** success → JSON-stringified in `content[0].text`. Error → `isError:
true` + one-line `"<status> <type>: <message>"`.

**Special case:** `td_execute` returns `200` even when user Python raises, so
Claude sees the exception as a code error (reasonable) rather than a
transport failure (confusing).

## Testing

**Unit (no TD needed):**
- `tests/api.test.ts` — fake HTTP server; exercise each tool's client logic;
  assert `Authorization` + `Host` headers and payload shapes.
- `tests/python_api_test.py` — stub `op()`/`ui`; hit each endpoint with
  `requests`; cover happy path, missing token, wrong token, bad host.

**Integration (manual, real TD):**
- `tests/manual.md` — numbered smoke-test checklist. `npm run smoke` calls
  each of the 9 tools once and prints pass/fail.

**Binary-trust closure:**
- `scripts/extract_tox.py` dumps the Python DATs out of `TouchAPI.tox` into
  `toe/src/td_api.py`. README mandates running this before committing any
  `.tox` change and diffing the result. This closes the "binary blob you
  can't review" hole flagged in the satoruhiga review.

## Security posture (explicit)

All six items confirmed in brainstorming:
1. Bind `127.0.0.1` only (not configurable).
2. Bearer-token auth, constant-time compare.
3. `Host` header whitelist.
4. No CORS headers (browser-unreachable).
5. `Rotate token` custom parameter.
6. Request log (in-memory ring + file mirror).

## Distribution

Local-only install for v1 (user's choice C2). Install instructions:

```
/plugin install C:/Users/zachm/Touch
```

No marketplace publication, no release pipeline. `dist/` is checked in so
users can install without `npm install`/`npm run build`.

## Out of scope / future

- Publish to a marketplace.
- OS-keychain-backed token storage (Windows Credential Manager / macOS
  Keychain). File-based is adequate for v1.
- `td_connect` standalone — absorbed into `td_create`'s `inputs:` argument;
  revisit only if users ask.
- Extracting the HTTP client into a reusable package (approach β in
  brainstorming). Can refactor later in ~30 min if a second consumer appears.
